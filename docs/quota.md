# Квоты Yandex Cloud

На 23.10.2026 в каталоге `default` (`b1g2ett5h4qn2kbsh6gr`) действуют
ограничения, которых не хватает для кластера:

| Ресурс | Факт | Нужно |
|---|---|---|
| SSD-диски в `ru-central1-d` | **10 ГБ всего** (диск 20 ГБ не создаётся) | ≥ 80 ГБ |
| HDD-диски в `ru-central1-d` | создание 30 ГБ отклонено | не используем |
| ВМ в `ru-central1-a` | `Resource allocation is restricted` | 8 vCPU (если вернём зону) |
| Зона `ru-central1-b` | `Zone is not available` | не используем |

Проверено экспериментально: ВМ 2 vCPU / 2 ГБ в `ru-central1-d` создаётся,
диск 10 ГБ создаётся, второй диск (даже 1 ГБ) — уже нет.

## Что сделать в консоли

1. Открыть **Yandex Cloud Console → каталог default → Квоты**.
2. Запросить увеличение:
   - `compute.disks.ssd.size` (объём SSD-дисков) — до **100 ГБ**;
   - `compute.instances.count` — до 6;
   - `compute.vcpu.count` — до **8–16**;
   - `vpc.externalAddresses.count` — до 8.
3. Проверить статус биллинг-аккаунта: пробный период активен, платёжный метод
   привязан. Сообщение `Resource allocation is restricted` часто означает
   исчерпанный пробный период или приостановленный биллинг.
4. После одобрения квот повторить:

```bash
cd infra/terraform
export AWS_PROFILE=diploma
terraform apply
```

## Если квоты не увеличат

Резервный вариант — одна нода вместо трёх (не соответствует ТЗ) либо
managed Kubernetes с минимальной конфигурацией (тоже требует квоту на диски).
Без дискового лимита кластер не поднять, поэтому увеличение квоты —
обязательный шаг.
